# Multi-Language Support (ID & EN)

## Context

Aplikasi Wealth saat ini menggunakan **bahasa campur ID/EN tanpa pola yang konsisten**: form labels dalam Bahasa Indonesia ("Nama Akun", "Harga Rata-rata"), tapi empty states dan navigation dalam English ("No Accounts Yet", "View All", "Dashboard", "Stocks"). Tone juga tidak konsisten — placeholder "Nama kamu" (casual) berdampingan dengan label formal "Email". Tidak ada i18n library yang terpasang, semua string di-hardcode di JSX. `<html lang="en">` juga hardcoded di `src/app/layout.tsx`.

Tujuan plan ini:
1. **Pasang infrastructure i18n** (`next-intl`) supaya app bisa switch antara Bahasa Indonesia dan English.
2. **Sisir & rapikan** semua user-facing string ke glossary konsisten (tone formal "Anda", technical terms standardized).
3. **Auto-detect** bahasa user dari browser `Accept-Language` header, fallback ID, dengan toggle manual di header.

Total scope: ~180–200 unique strings, ~25 file terdampak (auth, dashboard, forms, navigation, dialogs, lists).

Keputusan yang sudah disepakati:

| Keputusan | Pilihan |
|-----------|---------|
| i18n library | **`next-intl`** (App Router native, type-safe) |
| Default language | **Auto-detect dari browser**, fallback `id` |
| Tone Bahasa Indonesia | **Formal** ("Anda", bukan "kamu") |
| Approach | **Full setup sekaligus** dalam 1 PR besar |

## Working Agreement

- **Branch**: `feat/i18n` (cut dari `develop`).
- **Per sub-step di tracker = 1 commit**. Setelah tiap sub-step, AI **stop dan tawarkan commit + test**. Jangan lanjut tanpa konfirmasi user.

## Architecture

### Library: `next-intl` (v3+)

- Native App Router support (Server Components + Client Components)
- Type-safe message keys via TypeScript
- ICU message format (plural, formatting)
- Middleware-based locale detection
- Format helpers untuk numbers/dates/currency

### File Structure (Target)

```
src/
  i18n/
    config.ts                 # locales = ['id', 'en'], defaultLocale = 'id'
    request.ts                # getRequestConfig untuk RSC
    routing.ts                # routing config (cookie-based, no URL prefix)
    messages/
      id.json
      en.json
  middleware.ts               # next-intl middleware
  app/
    [locale]/                 # locale segment
      (auth)/...
      (dashboard)/...
      layout.tsx              # <html lang={locale}>
  components/
    LanguageSwitcher.tsx
```

### Routing Strategy: Cookie-based (`localePrefix: 'never'`)

URL tidak berubah saat user switch language. Locale disimpan di cookie `NEXT_LOCALE`. Cocok untuk app finansial pribadi yang gak butuh SEO multilingual.

### Message Key Convention

Hierarchical, snake_case di leaf, namespaces:
- `auth.*` (login, register)
- `nav.*` (sidebar items)
- `dashboard.*` (portfolio cards, summaries)
- `accounts.*` (account-related)
- `transactions.*` (transaction-related)
- `holdings.*` (stocks, crypto, gold lists & forms)
- `common.*` (save, cancel, delete, edit, etc.)
- `errors.*` (validation, API errors)

Contoh:
```json
{
  "auth.register.title": "Buat Akun",
  "auth.register.subtitle": "Daftar untuk mulai melacak aset Anda",
  "dashboard.portfolio_total": "Total Portofolio",
  "dashboard.cash": "Tunai",
  "common.save": "Simpan",
  "errors.insufficient_balance": "Saldo tidak cukup — tersedia: {available}"
}
```

### Locale Detection Flow

1. **First visit**: middleware baca `Accept-Language` → match ke `id`/`en` → set cookie `NEXT_LOCALE` → render.
2. **Repeat visit**: baca cookie → render.
3. **Manual switch**: `LanguageSwitcher` set cookie + `router.refresh()`.

### Currency & Date Formatting

- Currency tetap IDR di kedua locale (tidak auto-convert). Format separator ikut locale (`Rp 10.000.000` di ID, `Rp 10,000,000` di EN).
- Date: ID pakai `15 Mei 2026`, EN pakai `May 15, 2026`. Pakai `useFormatter` dari next-intl.
- Existing `useFormatCurrency()` hook (`src/lib/format.ts`) di-refactor untuk konsumsi locale dari next-intl.
